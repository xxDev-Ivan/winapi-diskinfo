# DiskInfo

Консольна утиліта для Windows, яка збирає системну інформацію через WinAPI без сторонніх бібліотек. За призначенням схожа на `wmic`, `Get-PSDrive`, `df`, `lsblk`, `top`.

Лабораторна робота №3 з дисципліни «Системне та мережне програмування».

## Можливості

| # | Модуль | Що робить |
|---|--------|-----------|
| 1 | Диски | Перелік логічних дисків: буква, повний шлях, статус доступності |
| 2 | Типи дисків | Тип накопичувача (HDD/SSD, USB, CD/DVD, мережевий, RAM-диск) з поясненням |
| 3 | Файлова система | Мітка тому, серійний номер, макс. довжина імені, назва ФС, прапори (стиснення, EFS, ACL, журнал USN, регістр, Unicode, транзакції тощо) |
| 4 | Місце на диску | Загальний розмір, вільне місце, доступний простір у ГБ і МБ, відсоток завантаження |
| 5 | Пам'ять | Завантаження RAM, фізична пам'ять, pagefile, віртуальна пам'ять (`GlobalMemoryStatus` і `GlobalMemoryStatusEx`) |
| 6 | Комп'ютер | NetBIOS-ім'я, DNS hostname, DNS domain, FQDN, Physical-варіанти |
| 7 | Користувач | Ім'я поточного користувача, ознака запуску з правами адміністратора (UAC) |
| 8 | Каталоги | System32, Windows, Temp, робочий каталог програми |
| 9 | Спостерігач | Відстеження змін у каталозі з логуванням часу, типу події та імені файлу |

## Використані WinAPI

| Група | Функції |
|-------|---------|
| Диски | `GetLogicalDrives`, `GetLogicalDriveStrings`, `GetDriveType`, `GetVolumeInformation`, `GetDiskFreeSpaceEx` |
| Пам'ять | `GlobalMemoryStatus`, `GlobalMemoryStatusEx` |
| Комп'ютер і користувач | `GetComputerName`, `GetComputerNameEx`, `GetUserName`, `OpenProcessToken`, `GetTokenInformation` |
| Каталоги | `GetSystemDirectory`, `GetWindowsDirectory`, `GetTempPath`, `GetCurrentDirectory` |
| Моніторинг змін | `FindFirstChangeNotification`, `FindNextChangeNotification`, `WaitForSingleObject`, `FindCloseChangeNotification` |
| Допоміжні | `FindFirstFile`, `FindNextFile`, `CompareFileTime`, `CreateDirectory` |

## Вимоги

- Windows 10 або новіша
- Visual Studio 2019/2022 з компонентом «Desktop development with C++»
- Платформа x86 або x64

## Збірка

1. Відкрити рішення у Visual Studio.
2. Перевірити налаштування проєкту (Properties, All Configurations):
   - Advanced → Character Set: `Use Multibyte Character Set`
   - Linker → System → SubSystem: `Console`
3. Файли з кирилицею мають бути збережені в кодуванні Windows-1251 (Cyrillic, codepage 1251), а в `main()` викликається `SetConsoleOutputCP(1251)`.
4. Вибрати конфігурацію `Debug | x64` і виконати Build → Build Solution.

## Запуск

Запускати через `Ctrl+F5` (Start Without Debugging), щоб консоль не закрилась після завершення.

Пункти 1-8 виводяться одразу. На пункті 9 програма переходить у режим очікування змін.

### Спостерігач за каталогом

За замовчуванням відстежується `C:\DiskInfoWatch` (створюється автоматично). Шлях задається змінною `path` у функції `WatchDirectory()` у файлі `Watcher.cpp`. Якщо немає прав на запис у корінь `C:`, потрібно вказати інший каталог, наприклад `D:\\TestForTask9`.

Програма обробляє 5 сповіщень і завершується. Для перевірки у відстежуваній папці достатньо створити файл, змінити його, перейменувати та видалити.

Відстежувані прапори:

| Прапор | Подія |
|--------|-------|
| `FILE_NOTIFY_CHANGE_FILE_NAME` | створення, видалення, перейменування файлів |
| `FILE_NOTIFY_CHANGE_DIR_NAME` | створення, видалення, перейменування папок |
| `FILE_NOTIFY_CHANGE_LAST_WRITE` | модифікація файлу |
| `FILE_NOTIFY_CHANGE_ATTRIBUTES` | зміна атрибутів |
| `FILE_NOTIFY_CHANGE_SIZE` | зміна розміру |

### Формат логу

Лог записується у `DiskInfo_log.txt` у робочому каталозі програми (режим дописування):

```
[2026-10-26 20:06:39] | СТВОРЕНО ПАПКУ (DIR_NAME) | Нова папка
[2026-10-26 20:06:51] | СТВОРЕНО ФАЙЛ (FILE_NAME) | test.txt
[2026-10-26 20:07:05] | ЗМІНА РОЗМІРУ (SIZE) | test.txt
[2026-10-26 20:07:05] | МОДИФІКАЦІЯ (LAST_WRITE) | test.txt
```

Формат запису: `[час] | тип події | ім'я файлу`.

## Особливості реалізації

- **Імена змінених файлів.** `FindFirstChangeNotification` лише сигналізує, що в каталозі щось змінилось, але не повідомляє що саме. Тому після кожного сигналу програма робить знімок каталогу (імена, розміри, час запису, атрибути) і порівнює його з попереднім. Різниця визначає тип події та ім'я файлу.
- **Затримка після сигналу.** Перед знімком виконується `Sleep(300)`, щоб система встигла завершити запис і не виникало проміжних станів.
- **Кілька сповіщень на одну дію.** Одна дія в Провіднику (наприклад, створення та збереження файлу) може породжувати кілька сповіщень, тому лічильник подій не завжди збігається з кількістю дій користувача.
- **Недоступні диски.** Якщо `GetVolumeInformation` повертає помилку (наприклад, порожній привід), диск позначається як недоступний, а програма переходить до наступного.
- **`SetErrorMode(SEM_FAILCRITICALERRORS)`** вимикає системні діалоги «Вставте диск».
- **Віртуальна пам'ять у x64.** Значення ~134 217 727 МБ (128 ТБ) є нормальним: це розмір користувацького адресного простору 64-бітного процесу.

## Обмеження

- Шлях спостерігача та кількість подій (5) задані в коді.
- Використано ANSI-версії функцій (`...A`), тому імена з символами поза кодовою сторінкою 1251 можуть відображатись некоректно.
- Для отримання імен файлів використовується порівняння знімків; для великих каталогів з інтенсивними змінами краще застосовувати `ReadDirectoryChangesW`.

## Можливі покращення

- `ReadDirectoryChangesW` замість порівняння знімків
- Визначення типу накопичувача SSD/HDD (`DeviceIoControl`, `StorageDeviceSeekPenaltyProperty`)
- Benchmark швидкості читання/запису диска
- Перелік точок монтування та GUID томів (`FindFirstVolume`, `GetVolumePathNamesForVolumeName`)
- Інформація про процесор і версію Windows (`GetNativeSystemInfo`)
- Шлях до спостережуваного каталогу як аргумент командного рядка
